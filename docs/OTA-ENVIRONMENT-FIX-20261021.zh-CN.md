# OTA 更新器环境依赖修复（2026-10-21）

## 已确认的问题

连接的 E5 仍为 `e5-r20261019.163549-g85eabf34-s858382c8`。
上传的补丁却是 `e5-r20261021.074310-g99570375-sa38c8179` 到该 19 日版。
它在版本检查阶段被拒绝，没有进入应用事务，不能把这个错误解释为系统已降级。

独立的工具缺陷也已确认：补丁自带 BusyBox 有 272 个 applet，但没有 `mountpoint`；
生成的 bootstrap 和 RPC 激活代码均调用了它。原来的模拟测试没有覆盖此命令缺失。

## 公共修复（两仓库）

- SSH 上传先部署随包静态 BusyBox；随后使用该工具检查空间、校验上传文件和操作文件。
- 旧机内只需 SSH、shell、mkdir、cat、chmod，不要求 Python、SFTP、stat、df、awk、sha256sum、mountpoint。
- 执行前核对随包 BusyBox 的实际 applet 列表；工具不完整时在上传大补丁前明确失败。
- bootstrap 直接读取 `/proc/mounts`，RPC 激活读取 `/proc/self/mountinfo`，兼容绑定挂载及转义路径。
- 版本错误显示设备、补丁起点和目标；目标已是设备当前版本时提示检查输入方向。
- 不删除版本匹配规则，不自动颠倒补丁方向，不改写设备的版本文件。

## 验证与交付

两仓库 Linux OTA 回归各 88 项通过。新增测试覆盖缺少旧机工具、工具能力缺失、
空间不足、首次与重复挂载、挂载路径转义、反向补丁不写入文件或事务日志。

连接的 E5 在 `PATH=/no-device-tools` 下以真实随包 BusyBox 执行修正后的 bootstrap
状态检查两次，均无 stderr，绑定挂载数量保持 7；新 RPC 的挂载表识别及新引擎的
详细版本拒绝也在 ARM64 实机运行通过。只在 RAM 放置诊断脚本，结束后删除脚本；
未执行更新、回滚、重装或重启，不修改 NV、AT、无线配置及用户文件。

Windows 两仓库工具重编于 `out/tools/OpenWrt-Diff-Studio-envfix/`，保留拖放和日期提交号命名。
旧的完整发行 ZIP 和已生成的补丁不随源码修改而变化；需要用新版工具重新生成正确方向补丁。
本次未更新 Apple Silicon 二进制或重打所有机型固件包，不把旧二进制称为包含此次修复。
