# U30 Air 呼吸灯与首页电池电流（2026-10-22）

## 确认的缺陷

连接的 U30 Air 运行 7.2.8。实际充电器与 FGU 都报告 Charging、online=1，
灯的 trigger 已选 pattern，repeat=-1，曲线为 0/625、255/750、0/625、0/250。
但 PMIC 0x180 控制寄存器是 0x300，白灯的 RUN 与 steady TYPE 同时置位，
即实际仍常亮。相同现象可以用“先常亮，再调用既有 battery 事件”重复触发。

当前 SC27xx 驱动的 pattern_set 只设置 RUN，不清除先前的 steady TYPE。
pattern 触发器的初始软件模式切换不保证调用硬件 pattern_clear；脚本此前
直接选择 pattern，因而可能保留常亮模式。是否只有扩展坞触发此路径尚未
证实，不把扩展坞充电正常等同于 LED 硬件模式正确。

## 修正

U30 Air 电池灯从其他触发模式进入硬件呼吸前，先通过标准 brightness=0
停止原输出，再将控制权交给 pattern。已经运行的相同曲线不重复停启，保持
原 2.25 秒节奏、峰值、50% 分色、Full 白灯常亮、用户关闭选择、过热告警、
外部供电保持显示，以及拔电后原有倒计时。未增加轮询或软件动画，不改内核、
充电器参数、供电角色、网络、AT、校准及 NV。

## 看板电流

首页电池卡片复用 dashboard-info 已有 power.ua（FGU current_now，单位 µA），
显示为带正负号的 mA：正数充电、负数放电、零为 0 mA；缺失或无效值为 --。
实际显示电池净电流，不因 USB 在线或 Charging 字样强制改变符号。无电池的
F50/V50 根据既有 present=0 隐藏该行。新增中、英、土三语言说明，无新 RPC、
AT 请求或刷新任务。

## 首页排版调整

按用户要求将电流并入原状态行，顺序为 Charging · 3.94 V · +100mA · USB，
不再单独增加电流一行，状态行移除“电源”前缀，mA 前不留空格。继续保留
真实电流符号、缺失值处理、无电池机型兼容与三语言说明。36 个浏览器场景
和适用 i18n 回归通过，两个前端文件已同步到 U30 Air。

电池卡片补入与 CPU/内存/存储一致的电量进度条，保留单行状态布局；无电池或无有效百分比时隐藏。0%/100%/缺失与三语言移动端、桌面浏览器检查通过，已同步 U30 Air。
