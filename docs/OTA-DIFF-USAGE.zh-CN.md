# 差异 OTA：保留插件、配置与数据

## 使用

1. 在 OpenWrt Diff Studio 选择同一设备系列的旧版、新版完整 ZIP，也可以分别拖入“旧版完整包”和“新版完整包”框，分析并导出。
2. 新系统已有 OTA 插件：网页「系统 → 系统补丁」导入 `update.ota`。
3. 旧系统没有 OTA 或 Python：完整解压导出的 ZIP，运行 `OpenWrt-Updater.exe`（或 Python 入口）连接设备，完成首次迁移。
4. 查看变更并应用。电脑工具默认勾选更新完成后自动重启；也可取消，在工具内点击「重启设备」。升级不会重装、格式化或缩小根分区。

导出时保存窗口默认填入 `OpenWrt-patch-<机型>-<OP版本>-k<目标内核>-<旧版日期和提交号>-to-<新版日期和提交号>.zip`，
例如 `OpenWrt-patch-T551M-25.12.5-k6.18.54-20261019.163549-g85eabf34-to-20261021.074310-g99570375.zip`。
MU300 共用发行包标为 `MU300-F50-V50-U30Air`；跨 OP 版本时写为 `25.12.5-to-25.12.6`。
机型、版本与内核读取包内元数据，重命名输入 ZIP 不影响识别。
任意一版解析不出日期或提交号，就回退为 `OpenWrt-patch-<新版发行包文件名>.zip`，
去掉原文件名末尾的 `.zip`；命名解析失败不报错、不阻止导出。
用户仍可手动修改名称、目录，或选择 `.ota` 供网页导入。
每个输入框一次接收一个文件，拖入文件只选择输入，不会自动分析、连接或刷写设备。

## 更新范围

- 替换两版发行包之间变化的系统文件，支持新增、删除、文件与符号链接转换。
- 支持完整 Linux boot、内核、配套模块、基础运行库、软件依赖和 OTA 更新器自身。
- 不要求两版内核版本相同；不会把 boot 变化仅作为警告而漏写。
- 相同 SHA-256 内容只保存一份。boot 只有一份，不另塞完整 rootfs。
- 用户额外安装的插件、软件包记录及其文件保留；APK 数据库按包名合并，脚本数据库按记录合并。
- 保留用户配置、密码、账号、流量池、短信、个人数据和本机固件/NV。新默认配置只在设备没有该文件时添加。
- 系统文件上已有热修补也可升级，备份的是设备实际内容，便于撤销。

## 执行与恢复

更新程序使用新版包中的 ARM64 Python、运行库和静态 BusyBox，放入独立 RAM 环境运行。
网页与电脑采用同一条执行路径，替换 Python、libc、更新器自身不会替换正在运行的解释器。
更新状态查询也转到 RAM 环境。设备没有旧版 OTA/Python 时由电脑通过 SSH 引导，无需联网装依赖。
电脑端独占创建随机临时目录，不要求旧系统安装 `stat`。首次连接、检查后查询、失败重试、
重新打开更新器和设备重启后的状态查询均使用随包解释器；不会退回调用系统 `python3`。
首次安装或更新插件后自动重载 rpcd 并核验对象，不重启 rpcd、不丢失登录会话。
RPC 参数接收 rpcd 注入的 `ubus_rpc_session` 会话元数据，仍拒绝未知业务参数。
电脑端仅对本次明确勾选的更新自动重启，等到事务提交并释放工作锁后执行；
单独查看历史更新状态不会触发重启，正在写入或恢复时禁止重启。

写入前保存实际文件、包管理记录及 Linux boot 恢复副本和持久化事务日志。
保留设备当前启动参数、动态 A/B 角色与启动日志区域，只写识别出的 Linux boot，不修改 Android boot、misc 或 NV。
先为现有 boot 接入 switch_root 前恢复钩子，再更新文件，最后写目标 boot 并回读校验。
正常完成后重新启动；中断事务在进入根文件系统前使用独立恢复环境撤销。网页可撤销上次更新。

保留机型、来源版本、路径、内容校验、空间和互斥检查。这些用于避免刷错设备或破坏数据，
不再以模块变化、基础包变化、更新器变化或旧系统没有 OTA 为由拒绝生成差异包。

## 验证边界

自动验证使用临时文件系统、作为假分区的普通文件，以及 QEMU ARM64 解释器。
真实发行包验证检查导出、首次迁移、插件与配置保留、包记录合并、内核与模块更新及回滚。
这些不是实机断电、闪存硬件故障或每款第三方插件 ABI 兼容性的验证。


## 旧系统环境与补丁方向（2026-10-21）

桌面更新通过 SSH 上传随包的静态 BusyBox，再由它检查空间、计算校验和、
解压和建立独立的 Python 运行环境。旧系统只需 SSH、shell 及初次上传所需的
`mkdir`、`cat`、`chmod`；不要求旧系统安装 Python、SFTP、stat、awk、df、
sha256sum 或 mountpoint。启动前检查随包 BusyBox 的必要命令，缺失时明确报错。
挂载检查直接读取内核挂载表，不使用 mountpoint，也不重复建立已有的绑定挂载。

差异包有方向：旧版必须是设备当前安装的版本，新版是希望安装到的版本。
版本不匹配时，工具会列出设备、补丁旧版与目标版本；如果设备已是补丁目标，
会提示检查两份输入是否选反。这不会自动交换包、降低版本、重装或改写设备版本号。
修复工具不会改写已生成的补丁；请用新版 Diff Studio 重新生成，以携带修正后的运行环境。
