# U30 Air PD 扩展坞：USB 主机与充电分离

## 故障与原因

原厂 Android 能通过带 USB-C PD 充电口的扩展坞同时充电与连接 USB 外设。
此前主线内核缺少 UMP9620 PD 控制器驱动，只有 VBUS 检测、充电类型识别和手动 USB 角色控制。
手动主机模式把 USB 数据角色和 OTG 升压供电绑定起来，无法完成扩展坞所需的 PD 数据／供电角色协商。

## 修改

- 将原厂 GPL 驱动中的 UMP9620 寄存器、时钟与校准操作接入主线 TCPM，使用内核既有 PD 状态机。
- 硬件完成 Type-C DRP 检测；IRQ、VBUS 事件驱动状态更新，无周期轮询或用户态反复切换角色。
- DWC3 数据角色与充电器供电角色独立：主机模式可以保持受电，只有成为供电端才开启 OTG 升压。
- 为 BQ256xx 板级充电器注册真实的 OTG regulator，并在 PD 合约生效后交由协商电流管理输入限制。
- 仅声明 5 V：受电上限 2 A，供电声明 500 mA；未移植原厂 PPS／高压 PDO。
- U30 Air 的 mu300-usb 优先使用内核 Type-C data_role，请求数据角色切换时不直接操作充电器寄存器；旧内核保持原兼容路径。
- 处理驱动加载前已插线的初始状态；TCPM 在 .remove 中先注销，避免 devres 提前释放异步创建的 PD 对象。
- 接收中断按原厂顺序读取单帧并清理 FIFO，避免把帧后残留字当成下一条 PD 消息；保留重复 TX 完成保护。
- 仅绑定具有 use_pdhub_c2c 的 UMP9620 电池板；其他机型不会因启用内核选项而套用该硬件控制。

## 验证进度

- 6.18.54 与 7.2.8 正式版 Image、全套配套模块均已编译完成。
- U30 Air 已运行测试内核，修正版控制器以匹配 BTF 的模块热加载。
- 电脑 USB 连接识别为 USB device + power sink，管理网络、热点和蜂窝保持运行。
- 修正资源释放顺序后再次卸载／加载，无新增内核 WARN。
- Linux 下 26 项 USB 管理与 PD 回调测试通过，包括主机受电、主机供电、设备受电、错误返回、重复 TX 完成保护、接收帧边界与错误清理。
- 用户确认：扩展坞接上充电器后，手动切主机模式即可使用；接受保留手动切换。
- 对应内核日志确认 USB host + power sink，RTL8153 网卡成功枚举并进入 LAN，链路 carrier on。
- 自动切换为主机未通过，因此不宣称实现；PD 接收清理的收尾修正后，还未再次验证同一扩展坞。

正式版内核与 203 个配套模块文件已同步写入设备，镜像回读校验通过。部署期间保留完整旧内核和配套模块，启动后的管理检查通过才解除自动回退。

正式重启检查：U30 Air 已启动 7.2.8 #33，内置 ump9620-tcpm 驱动绑定成功，不再依赖临时测试模块。电脑 USB 数据角色为 device、供电角色为 sink；192.168.77.1 管理连接正常，5 GHz／80 MHz 热点已启动，蜂窝 WAN 已获取 IPv4 与 DNS。根分区以读写方式挂载，无新增 BTF／驱动 WARN；自动回退已确认解除。
