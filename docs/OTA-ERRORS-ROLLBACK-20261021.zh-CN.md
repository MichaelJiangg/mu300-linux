# OTA 错误展示、重启与撤销循环修复（2026-10-21）

## 用户可见行为

- Diff Studio、桌面更新器和网页插件共用同一份中英文错误解释。
  版本起点不匹配、机型不匹配、权限、空间、校验、连接、忙碌、恢复冲突等均显示可操作说明。
  未归类错误显示本地化概述；原始 JSON、错误码和完整诊断仅放在可展开的技术详情。
- 网页请求重启后停止状态轮询，重复点击无效；正常连接中断进入等待重连，不再报 XHR 红字。
  明确拒绝重启的业务错误仍显示。后端先返回确认，延后约两秒执行 sync/reboot，期间持续持有更新互斥锁。
- 撤销按钮先做只读检查，验证全部恢复副本，再显示内容、权限、所有者、扩展属性或启动镜像冲突。
  执行时再次核验；真实后续修改不强行覆盖。已恢复为原内容的文件允许继续撤销。

## 已确认的运行环境缓存缺陷

旧代码用 `copytree(..., symlinks=True, dirs_exist_ok=True)` 合并到固定的 `etc/unisoc-ota/runtime`。
这不能替换已有的同名符号链接，因此“更新—撤销—再更新”会在 libatomic、musl 链接处报 Errno 17。
现改为事务内独立的 `backup-<编号>/runtime`；撤销从事务记录指向的环境执行，兼容旧记录的固定目录。
根目录及文件内的符号链接均保持链接，不展开成重复的库目录。

## 清理与持久性

- 成功后只保留最近一次事务的数字编号备份（含一份恢复运行环境）。
- 新事务准备阶段保留旧备份，最多另有一份新准备目录；准备失败清理本次目录。
- 发布新事务记录后才允许删除旧备份；不确定事务记录是否已发布时，保留恢复目录。
- 写入失败且恢复成功后，恢复上一事务记录并删除本次失败备份，不占掉上次成功更新的撤销机会。
- 下次更新在引擎锁内清理未引用的数字编号目录；成功迁移后清理旧固定 runtime 缓存。
- 不清理用户自命名的备份目录，不修改用户插件数据、NV、无线配置或正常启动流程。
- 恢复环境文件、子目录和事务目录同步落盘后，才发布可用于恢复的事务记录。

## 验证与限制

两仓库 OTA 回归各 106 项通过。包含连续三轮更新—撤销—再更新、两个原报错符号链接、
准备失败保留上一恢复环境且无目录累积、新版本写入失败后仍可撤销上一成功版本、中断遗留清理、更新器恢复自己的 rpc.py、
真实本地修改拒绝、备份损坏前置拒绝、重启确认窗口的真实子进程持锁。
所有恢复写入测试仅在临时文件系统内运行，没有对连接设备执行撤销或重启。
网页脚本测试覆盖正常重启、XHR 断开、业务拒绝、撤销预检及权限；浏览器覆盖中英文切换与折叠技术详情。
当前无法 SSH 连接 E5/T551M 或 MU300 管理地址，用户所报 rpc.py 冲突的实际内容/权限差异尚未读取，不能断言是假冲突。

Windows 工具位于两仓库 `out/tools/OpenWrt-Diff-Studio-errors/`。
新生成的补丁同时携带当前引擎、网页视图、错误解释模块与匹配 ACL，无需先重打整套 rootfs。
旧补丁及旧完整包不会自动改变，需用新工具重新生成；本次未更新 Apple Silicon 二进制或所有机型完整发行包。
