# 分卡射频开关改为 SFUN

日期：2026-10-19。适用 MU300、F50、V50 的公共双卡实现及 U30 Air 当前活跃卡控制。

## 已确认的依据

用户实测 `SFUN=5` 后 `CFUN?` 为 0，`SFUN=4` 后恢复为 1。记录未注明具体机型和基带版本，不能据此宣称全部型号已实测。

E5 仓库保存的实际原厂 RIL 二进制与对照源码都使用 `SFUN=5/4` 控制协议栈。原厂 E5 `libimpl-ril.so` SHA-256 为 `c0e86a5a6d7402a3d126e411fdb956deb8a6454763d55505c3ba64f839d0c14b`，其 `isRadioOn` 将 CFUN 0、2 视为关闭，1 视为开启。完整原厂版本未在本轮重新核实。U30 Air 已有原生热切卡流程本来就使用 SFUN 关闭／开启，既有实机时序依据见 FINDINGS 第 74 节。

旧分卡控制器使用 CFUN 4/1，与上述协议栈开关不一致；此前 CFUN 数值回读通过不能证明无线电关闭语义正确。

## 源码修正

- 当前运行卡和普通双卡按卡发送 `AT+SPACTCARD=<0|1>;+SFUN=5/4`，关闭回读接受 CFUN 0 或 2，开启要求 1。旧飞行模式值 4 可以作为迁移前状态识别，但不能当作新的 SFUN 关闭成功。
- 同步冷启动允许位执行和热初始化禁用策略；不另留 CFUN 写命令作为兜底。
- 两卡都关闭的全新启动不能把 CFUN 0/0 当作已经初始化：首次仍完成原有 SIM 上电、模式设置和早期回放，最后对两卡执行 SFUN 5，不启动 RF。只有检测到本轮已有初始化、原有活跃栈或两卡都不存在时才跳过。后续单独开启一张卡不会漏掉首次初始化，也不会反复重做模式和回放。
- `SFUN=5` 后 CFUN 为 0、SIM 仍有供电时，开启直接走 SFUN 4，不误触发整套冷启动。真正未供电的 SIM 继续交给既有初始化器。
- 通用单栈启动器识别有效的关闭状态 0/2，以及升级前遗留的飞行模式 4，再进入已有 SFUN 开启流程；不增加重试服务或定时轮询。
- U30 Air 未活跃槽仍只保存权限，不直接对其发射频命令；当前卡被用户关闭后允许从 0/2 状态进入原有切卡流程。原有旧卡 RF 关闭、SIM 掉电、目标 SIM 上电、路由选择和 SFUN 开启顺序保留。
- 保留已有明确允许位、SIM2 默认关闭及主动切 SIM2 时开启的策略、数据手动关闭意图、原有 AT owner 和互斥机制。

## 离线验证

- 分卡射频 14 项、普通双卡初始化 10 项、U30 集成 8 项通过，包含宿主可用的多种 shell。
- U30 冷启动 38 项、热切卡 37 项、普通上网卡切换 11 项通过。
- 覆盖两卡独立开关、两卡同时关闭、0/2 两种关闭回读、旧飞行模式迁移、默认关闭、显式开启、冷启动首次握手、SIM 未供电与仅 RF 关闭的区分、U30 关闭当前卡后切换。
- 其余型号未做本轮实机验证；未构建新的发行包。旧版 CFUN 的历史实测记录不能替代新版 SFUN 的实机验证。

## V50 实机验证

2026-10-19，用户连接的设备已由运行时型号确认是 V50，内核 7.2.8。实际基带版本：

```text
Platform Version: MOCORTM_V2_23A_W25.33.6_Debug
Project Version: QogirN6Pro_PS
BASE Version: 5G_MODEM_V2_23A_W25.33.6
HW Version: ums9620_modem
08-16-2025 06:22:39
```

通过网页相同的 ubus 异步接口进行操作，而非只手工发送 AT。更新 8 个公共脚本，逐文件 SHA-256 校验，保留旧文件备份；未更换内核或操作 NV 分区。

| 测试 | 实际结果 |
| --- | --- |
| SIM2 单独关闭 | CFUN 为 1/0，另一卡仍开启，两卡 CPIN 均为 READY |
| 两卡关闭、只恢复 SIM2、恢复双卡 | 依次为 0/0、0/1、1/1，作业均成功 |
| 两卡关闭后等待后台恢复活动 | 8 秒观察内没有被自动重新打开 |
| 已开启卡重复开启 | 作业成功，允许位保留 |
| 手动关闭数据，再关闭／恢复当前卡 RF | autostart 仍为 false，没有擅自 ifup |
| 非法卡槽、未确认请求 | 拒绝，射频和设置未变 |
| 切卡互斥门闩被占用 | 返回 modem_busy，未改允许位或射频 |
| 手动关闭数据且 SIM2 RF 关闭，主动切到 SIM2 | 自动启用 SIM2，实际与保存上网卡均为 1，数据仍保持手动关闭 |
| SIM1 被用户禁用时切回 SIM1 | 明确拒绝，未擅自开启；手动启用后正常切回 |
| SIM2 关闭后正常重启 | 新 boot ID 下仍为 1/0；SIM 均保持供电 |
| 两卡都关闭后正常重启 | 新 boot ID 下仍为 0/0，初始化完成，数据接口等待用户启用 |
| 全关重启后只启用 SIM2，再启用 SIM1 | 分别为 0/1 和 1/1，没有把另一卡一起开启 |
| 测试结束恢复 | 两卡允许位 1/1，实际 CFUN 1/1，SIM1 为上网卡；WAN up=true、autostart=true |

复查期间发现全关冷启动可能提前跳过初始化的源码缺口，补充了对应回归后才进行第二轮重启验证；没有把它报告成已复现的原版基带崩溃。

第二轮启动早期 SSH 会话曾断开，重连后同一轮系统与 RIL 初始化均正常。另看到 mmc2 的控制器探测错误，尚未归因，不能据此宣称整机所有内核问题都不存在；本轮未改存储或 SD 控制器驱动。根分区 mmcblk0p76 保持读写，没有在收尾检查中发现 EXT4/I/O 错误或 CP assert。

运行证据在本地忽略目录 `work/v50-sfun-live-20261019/`，包括初始化快照、运行／切卡测试、两轮重启结果和部署文件摘要。验证只覆盖这台 V50 的射频状态、协议栈与数据控制边界，不等同于所有机型的长期移动、通话／短信或物理发射功率实测。
