# 系统补丁页面、重启状态与恢复副本清理（2026-10-21）

## 已确认缺陷

旧页面用持久化的 job.status=complete 无条件显示“请重启”。该记录跨重启保留，
因此即使设备已启动新版本，仍重复提示。这不等于更新失败或没有重启。

## 修复

- RPC 完成任务时记录内核 boot_id；同一次开机提示重启，boot_id 改变后显示已重启。
  旧记录没有 boot_id 时，只显示“上次操作已完成”，不根据时间或成功标志猜测重启状态。
  不删除更新记录或恢复副本来消除提示。
- 页面复用看板 mu300.common 的 CSS、语言选择和主题令牌，支持亮／暗色和手机布局。
  将当前版本、导入更新、恢复副本、最近操作分区展示；说明网页应导入 update.ota。
- 展示恢复副本实际占用空间，提供“删除恢复副本”。必须先弹窗确认：显示约可释放空间，
  明确不可再撤销，同时保留当前系统、插件、配置与用户数据。取消不调用删除 RPC。
- 删除与更新／恢复／重启共用 job.lock，另持有引擎及系统升级锁。待恢复事务不允许删除。
  只删除本引擎保留的 backup-数字 目录及旧 runtime 目录，不跟随符号链接或 journal 任意路径。
  删除前先持久化撤销不可用标记；删除中断可以重试，不会误用半份恢复副本。
  保留 current.json、版本身份及事务结果；删除后仍能创建新的更新及恢复副本。
- 通过 rpcd 写 ACL 暴露固定 discard_recovery 方法，不增加任意命令或路径参数。
