短信转发融合适配（2026-10-10）

参考 D:/Git/e5-linux 的 luci-app-t551m 短信转发页面与 e5-sms，
在独立 luci-app-mu300 中实现功能融合，不引入 E5 AT、ModemManager 或 Python 服务依赖。

使用方法
1. 蜂窝 → 短信转发。选择“所有 SIM 共用”或“按 SIM 独立配置”。
2. “正在编辑”选择共用配置、SIM 1、SIM 2，分别设置并保存。
   各配置独立保存启用状态、渠道、凭据和黑名单。切换编辑对象前会提示未保存修改。
   独立模式按短信实际来源卡路由，与当前上网卡及看板查看卡无关。
   未激活配置不会自动处理短信，但允许单独发送测试消息。
3. Webhook 可选 JSON、Bark、PushPlus、ServerChan、Telegram、企业微信、钉钉预设。
   预设填表后请替换 YOUR_KEY / YOUR_TOKEN 等凭据再保存。
   钉钉需要加签时仍使用原来的“钉钉机器人”渠道。
4. 支持 GET / POST、JSON / 表单编码 / 纯文本、附加请求头、1–120 秒超时。
   默认 12 秒。JSON 模板为空保留原来的 from/text/date 数据格式。
   占位符为 {from}、{text}、{time}、{sim}、{device}、{kind}。
   JSON 占位符放在字符串值中；嵌套对象/数组也支持。
   URL、表单值自动百分号编码；替换仅执行一遍，不解释短信里的占位符或命令。
   GET 只发送 URL 参数，不发送正文。附加头为静态 Name: value，每行一个。
5. SMTP、钉钉加签、本机短信、号码/关键词黑名单、三种模板语言全部保留。
   电源通知始终走共用配置，请启用共用配置并填写渠道。
   F50 无有效电池数据时不可启用电源通知，不影响短信渠道；有电池的设备继续支持。
   充电状态变化和电量跨过 5/20/40/60/80/100% 时通知。
6. 页面继续复用插件弹窗、toast、loading；兼容 Aurora 与官方主题的样式变量。

兼容与安全
- 旧 config.json 和旧密码原位保留，默认 shared；无自动开启或复制凭据。
  新增 config.sim0.json、config.sim1.json、mode，位于 /etc/unisoc-modem/forward/。
  配置目录 0700，文件通过 umask 077 创建。编辑返回“已配置”状态，不返回密码/加签密钥。
- SIM 1 与 SIM 2 独立收件游标；启用、换渠道、切换配置模式先建立历史屏障。
  不把历史同步当新短信，不自动补发失败投递。每个合格新事件只尝试一次。
- 电源游标单独存放于 state.power，不能覆盖尚未初始化的短信收件游标。
- 仍只支持公网 HTTPS，校验 TLS、拒绝私网 DNS 结果、固定解析地址、不跟随重定向。
  未照搬 E5 的明文 HTTP、命令式 curl、失败自动重试和含发件号码的日志行为。
  Host、Content-Length 等影响请求边界的附加头禁止覆盖。凭据/正文不写投递记录。
- 单服务处理两个短信池，不增加 AT 轮询。测试任务非阻塞准入，不累计排队进程；
  有投递正在执行时，保存/测试明确返回忙，避免 RPC 超时后误认为未保存。
- 最近 30 条 RAM 记录只含时间、事件类型、渠道、来源 SIM、HTTP 状态和有限结果码。
  HTTP 成功表示服务端接受请求，不等于最终邮箱/手机已经收到推送。
