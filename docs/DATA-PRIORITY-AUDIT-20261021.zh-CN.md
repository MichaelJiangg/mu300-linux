# 基带偏好设置链路核对

对照 `D:/Git/ufi_tools_uni_app` 独立版 `StandaloneNetworkController.kt`：
“基带优先数据卡”开启时按顺序发送 `AT+CEUS=1`、`AT+CEMODE=2`。
这里记录程序对应关系，不以界面名称推断射频性能或标准含义。

MU300 的公共 `mobile-data` 已经内置这两条设置，正常开机预热、切换上网卡、
射频恢复和再次拨号通过 `radio_on` 调度同一异步任务。没有持久化成功标记，
后续恢复会重新设置。涵盖所有使用该公共脚本的机型及内核系列。

本次发现并补齐的缺口：手动 `sim-reset` 完成后没有直接调度，之前依赖
后续拨号补上；现在复用 `queue_data_priority`，数据关闭时也不必等重新拨号。
保留已有 SIM 探测和 SFUN 顺序，不新增等待，不开启用户关闭的射频或数据。
重启步骤失败不报告偏好设置成功，后台调度失败也不改变原来重启的成功结果。

专项回归覆盖两张卡、连续重启重新调度、禁用射频及原生双卡拒绝重启、
重启 AT 失败、后台调度失败，以及原有非阻塞和有限重试测试。
每条设置仍是首次加最多三次重试，以最终 OK 确认；耗尽记录失败，不无限轮询。

E5 仓库已有 MM 初始化结束／启用回调，本次仅扩展六个 profile 和重复回调测试，
没有再增加第二套运行时实现。

本次为源码核对及离线回归，未热部署、未编译打包，未作真实基带重启验证。
