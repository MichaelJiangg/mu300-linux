# 上游启动／更新问题同步与扩散验证

日期：2026-10-17。范围为 MU300 维护分支的公共实现，适用于 F50、V50、U30 Air；没有将 E5 的硬件实现搬入本仓库。本轮继续在 `fix/shared-issues-20261017` 工作，保留此前未提交更改。

## 来源与问题确认

- [#290](https://github.com/dikeckaan/mu300-linux/issues/290)：V50 经桌面安装器安装到独立 GPT 分区后，运行上游内置更新，通用 init 替换桌面 init，找不到根分区，进入约 302 秒的救援回退。`pmic-wdt-NOT-ready` 是这条失败路径的后续现象，不能直接当成基带或 watchdog 根因。
- [PR #295](https://github.com/dikeckaan/mu300-linux/pull/295)、[PR #296](https://github.com/dikeckaan/mu300-linux/pull/296)：更新前核对布局，通用启动镜像识别 `mu300root`。按本分支的现有 init、TF 选择和桌面更新架构适配，没有整套替换为上游脚本。
- [#226](https://github.com/dikeckaan/mu300-linux/issues/226)、[PR #283](https://github.com/dikeckaan/mu300-linux/pull/283)：部分 eMMC 在 HS400ES 初始化阶段持续返回 `-84`，重复初始化仍选择同一个失败模式，最终没有 `mmcblk0`，固件和系统也无法读取。上游报告者已确认新版冷启动恢复；这不是本轮对我方设备的实测结果。

## 实际修改

### 通用启动镜像与布局检查

通用 init 在原有 TF／未分配空间路径之外，支持内部 eMMC 上唯一名为 `mu300root`、ext4 标签也完全匹配的 GPT 分区。不会选中 TF 上的同名分区，也不接受重复名称或前缀相似的标签。

默认启动选择保持原逻辑：合法 TF 优先，之后是既有内部空闲区域，再检查独立分区。桌面安装器明确选择独立分区时，则保留这一明确选择，不扫描 TF 或另一片内部区域。

扩散检查发现，桌面启动镜像可以继承底层 TF 镜像的 `mu300-root-target=sd`。因此新 init 明确读取桌面 `part` 策略，避免“虽然增加了分区扫描，却仍被旧 TF-only 标记挡住”。`sd` 策略依旧禁止访问内部根区域。

通用与桌面分区启动共用 `boot/internal-ext4.sh` 中的原有离线检查，不新增另一套修复。健康文件系统只读取状态，跳过完整 fsck；确认错误的内部根在挂载前检查。新文件接入普通、通用 ramdisk 和桌面附加 ramdisk，更新后不会丢失对应检查。挂载后的 USB 模式策略仍在配置 gadget 前读取。

主线内核包声明 `gpt-root` 能力。更新器在系统目录切换、模块替换和写 boot 前核对布局，不兼容的内核包提前停止。userdata 镜像不交给不能启动它的通用 init；仍使用桌面安装器的对应更新流程，不为了识别布局挂载 Android userdata。

### 本地内核包与临时启动

更新器原先只用 Image＋generic ramdisk 计算安装身份，模块则在启动镜像校验之前就会替换。现在身份覆盖完整内核包；不同模块／能力内容不会仅因 Image 和 init 相同被报告为已安装。

模块写入移到启动镜像头、AVB 边界和镜像容量检查之后。验证通过的同一包重复执行仍跳过；不可用布局和错误启动头均不修改模块。

新增统一的 `mu300-next-boot --trial`：与已有切系统操作使用同一锁，重置失败次数并设置可回退的 Linux 试启动，不改变用户保存的默认系统。更新后使用已安装系统中的这份工具，避免仍运行在旧根目录时调用旧 API。若无法设置试启动会明确说明，不把“已写入 boot”误报为没有写入。

### eMMC 失败模式降级

新增 `0021-mmc-failed-timing-falls-back.patch`，采用 PR #283 的 MMC core 部分：仅时序初始化失败后，删除该 host 中失败的能力，让现有初始化重试选择下一模式，顺序为 HS400ES → HS200 → HS／DDR52 → HS。移除介质的错误不降低能力；正常 HS400ES 成功路径不降级。

不新增固定等待、重试轮询、默认降速或休眠限制。没有移植生产内核故障注入参数，也不修改 AT、开机回放、拨号或 NV。

## 验证

- 24 组公共回归共 **170 项：169 项通过，1 项按 root 环境条件跳过，无失败**。最后提取公共 fsck 后，受影响的通用启动、桌面 fsck、桌面安装器、ramdisk、TF 和静态回归重新通过。
- 图形安装器后端另有 **195 项：191 项通过、4 项按仓库／环境适用条件跳过，无失败**，覆盖更新、切系统、续装及卸载工作流。
- 实际执行 init 的存储选择代码，覆盖旧 TF 标记＋明确 part、TF 优先、region 优先、分区不存在、挂载失败、重复分区、错误标签及非 MMC 设备。
- 实际执行更新函数，覆盖不兼容／缺失包在 `apply_one` 前拒绝，模块内容不同的本地包更新，同一包重复跳过，以及错误启动头不替换模块。
- 实际执行 `mu300-next-boot --trial`，在临时 misc 文件验证 A／B 两个 Linux 槽、CRC、尝试次数、只改 32 字节控制区，以及 android／linux／未保存默认值均保持原样。
- MMC 测试编译执行补丁的实际 C 函数，覆盖各级能力掩码、卡自身能力和 `ENOMEDIUM`。补丁分别零 fuzz 应用于本地 6.18.54、7.2.8 源码副本，并使用各自实际配置与编译命令生成 `mmc.o` 通过。源码／输出卷只读，编译产物仅在临时目录；没有把对象编译说成整包或实机验证。
- 其余扩散覆盖独立分区临时 loop／GPT、TF 容量与格式化、两槽启动链、原生部署文件保留、更新锁、SIPA TX 重试、电源回调、FGU、热点及 U30 Air PD／灯光。
- shell 语法及 `git diff --check` 通过。详细日志位于忽略目录 `work/upstream-refresh-20261017/`。
