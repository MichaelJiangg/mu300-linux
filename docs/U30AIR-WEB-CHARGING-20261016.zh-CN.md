# U30 Air 网页充电管理（2026-10-16）

## 用户入口与功能

网页「蜂窝 → 设备管理」，位于 USB 网卡卡片下方：

- 充电上限开关；停止阈值 50–100%，恢复阈值 20–95%，恢复必须低于停止。
- 临时充满一次：达到 100% 且充电器实际报告 Full 后，恢复原上限策略。
- 手动暂停电池充电、恢复自动充电。恢复自动仍遵守用户启用的上下限；需要越过上限时使用临时充满。
- 显示当前电量、充电状态及暂停原因，提供手动刷新。
- 中文、英文、土耳其语，跟随现有明暗主题及手机布局。

默认不启用上限，不主动改变用户的充电策略。配置在 `/etc/config/mu300-charge`，
属于更新时保留的 UCI 配置；上限和手动暂停会在开机应用。
没有电池的 F50/V50 隐藏该卡片，后端也拒绝控制，不读取其虚假 FGU 数值作为电池。

E5 仓库的公共网页卡片同样改到 USB 网卡下方，覆盖 E5/T551M/M8 的共享界面。
它继续使用原 e5-charge 配置和服务，没有换成 U30 Air 的后端。

## 对照 Android 插件与已有驱动

用户提供的「充电控制器（直供电插件）」通过 Android 的
`interface`／`zte_battery`／`battery_charging_enabled` 节点控制电池充电。
这些原厂专有节点在当前主线内核中不存在。

进一步核对已有 0009、0018 补丁及实际驱动，等效接口已经存在：

| 操作 | OpenWrt 接口 |
| --- | --- |
| 暂停电池充电 | `bq256xx-charger/charge_type` 写入 `N/A` |
| 恢复驱动正常充电 | 同一节点写入 `Fast` |

驱动只修改 CHG_CONFIG，并记录用户暂停意图用于后续 VBUS 检测；没有从网页直接写 I²C，
没有新造原厂私有节点，不调整输入限流、充电电压、电量校准或 NV，也不需要换内核。
`Fast` 是恢复充电的枚举命令，不代表强制快充协议或提高设定电流。

这里的“暂停充电”保留外部供电，不等于断开电池或实现了物理电池旁路。
端口为 OTG 供电端时，不写入恢复充电命令；待切回受电端后再恢复。

## 事件与功耗

没有照搬插件的 5 秒循环和 sysfs inotify：当前 FGU 只提供部分中断／外部电源通知，
不会为每次百分比变化发送 uevent；sysfs inotify 也不能可靠代替 SOC 检查。

- 使用已有 power_supply 热插拔入口处理电源事件。
- 启用上限或临时充满时，单个 ucode 进程订阅事件，并每 30 秒读取一次本地 SOC。
- 普通默认关闭和手动暂停不启动这个周期检查进程；GUI 关闭功能会停止服务实例。
- 临时充满完成且没有上限策略时，停止 SOC 定时器；进程如仍存在，仅阻塞等待事件。
- 网页只在进入、刷新和操作后读取状态，没有前端定时刷新；不发 AT，不新增拨号等待。
- 配置和硬件应用经同一个文件锁串行执行，只在控制意图变化时写驱动。

## 验证与实机应用

- 实际 OpenWrt ARM64 隔离容器运行生产 ucode，覆盖阈值滞回、持久化、手动暂停／恢复、
  临时充满、禁用策略、非法输入、OTG 供电角色和无电池机型。
- 另运行真实 ubus/uloop 监听，验证电源事件唤醒和无事件时 SOC 定时检查；
  不只校验后端单次调用或源码关键词。
- 生产网页通过三语言、明暗主题、手机／桌面布局与 USB 页面原有生命周期回归。
- 部署前确认 U30 Air 型号及 eMMC CID，使用独立 IPv6 地址，未修改同时连接的 F50。
- 实机暂停后 `charge_type=N/A`、`status=Not charging`、`online=1`；恢复后正常充电。
- 实机启用 70%／80% 策略时，当前 100% 电量立即暂停，服务进程正常运行。
- USB LAN、蜂窝 WAN 保持 up，输入限流仍为 2,000,000 µA。
- 测试后恢复部署前的默认配置：不启用上限，不手动暂停；用户可在网页自行开启。

本轮未通过放电验证实物达到下限后的恢复，也未重启或再次插拔 PD 扩展坞。
这些边界不能写成实物测试已完成；软件状态转换已在隔离环境验证。
