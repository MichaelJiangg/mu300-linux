# 短信池与列表列宽修复（2026-10-22）

## 已确认的问题

MU300 clean-tf-7.2 原生 smsd 和 AT 守护的直接投递写 /etc/mu300/sms，
SIM2 写其 sim1 子目录。面板默认 UCI 却指向 /etc/unisoc-modem/sms，只有
目录不存在才切回原生目录；两个目录都存在时，真实收件与页面读写分离。
转发服务也有相同的“按目录是否存在”选择，因此一起修复。

CLI list 的日期字段仅保证最少 21 字符，PDU 解出的带时区日期实际为
25 字符。RPC 固定按 21 字符切割，导致时区残片进入预览。此缺陷属于软件
展示和存储接入，与运营商无关；不能据此证明群友全部真实收件问题都已解决。

## 实现

- 新增同一 sms-pool.sh 解析器，CLI、直接 PDU 暂存、收件服务、AT 服务的
  环境、面板和转发共用，不再由各处自行按目录是否存在决定路径。
- 新装默认 /etc/mu300/sms。原生后端的旧默认 /etc/unisoc-modem/sms 及末尾
  斜杠形式作为兼容别名解析到原生池；不删除或自动混合旧目录记录，避免 ID
  冲突。用户明确通过 MU300_SMS_POOL 指定目录仍优先；其他自定义目录保留。
- 自定义 SMS 适配器保留其原有配置/默认目录，不强制迁到原生后端。
- SIM2 在调用侧只追加一次 sim1，保留后台发送事务的既有作用域。AT 端口、
  reader 所有者、启动/回放/拨号顺序及命令均未变；没有重开或重启实机 AT。
- 设置页默认目录同步，并说明更改目录后重启生效、历史记录不自动搬移。
- 列表识别标准带偏移的 25 字符时间，同时兼容原 21 字符列；保留完整时区。
  发送方 CLI 展示限宽 18，完整原文/发送方仍保存在原短信文件和 show 结果。
- JSON 对所有文本字段处理引号、反斜杠和控制字符，避免包含制表符的预览
  生成无效 JSON。没有改动 PDU、分段归并、去重或短信转发时序。
- rootfs 和最终 TF 包检查均将新共享库列为必需文件；没有新增常驻服务。
