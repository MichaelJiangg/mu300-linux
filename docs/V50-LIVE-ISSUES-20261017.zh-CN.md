# V50 公共修复实机部署

日期：2026-10-17。源码基线为 clean-tf-7.2 的 `5161859d`；本轮另补 iw-full 和 LuCI 模块导出修复，未重新打包。

## 启动和内核

- 连接时 V50 运行 Android A。使用现有安装器共享 helper，仅修改 misc 的 32 字节控制块，临时进入 OpenWrt B；不挂载根分区，不写 boot 或同步启动链。
- 首次进入 OpenWrt 后部署用户态 8 个文件，再更新包含 MMC 初始化失败模式回退补丁的 7.2.8 内核及完整 201 个配套模块。
- initramfs 同步更新实际所需模块和共享 init、内部 ext4 检查 helper。旧基础段里残留、已不在当前加载顺序中的其他内核模块没有保留；新的所需模块均存在于同一构建中。
- 通用 init 实机识别唯一 GPT 分区 mu300root，启动后 `/run/mu300-root-dev` 为 `mmcblk0@mu300root`。实际 BTF 和全部 201 个根分区模块摘要匹配。
- eMMC 仍运行 200 MHz、8 bit、HS400 enhanced strobe、1.8 V；本机成功路径未降速。未进行人为故障注入，不能以此证明失败回退已在真机触发验证。
- 原默认 Android 策略保留。此次使用试启动进入 OpenWrt，没有把默认系统改为 OpenWrt。

## 功能检查

- 热点为 AP，36 信道、80 MHz；USB 管理连接和 AT 命令正常。
- 用户声明未插外置卡、内置卡欠费。只验证 AT 响应及无可用 SIM 的状态，不把欠费／无卡导致的蜂窝不可用算作故障，也未验证蜂窝上网。
- 更新器实际读取根布局返回 `part`；未在设备运行完整系统更新、格式化或缩容。
- UCI 配置逐文件摘要在更新和重启后保持一致。
- 未发现根分区 ext4 错误、模块版本／符号错误或 Oops。启动时未使用的 mmc2 控制器仍有原有超时日志，不能等同于 mmc0 的根存储故障。

## 本轮实机补齐的两个缺口

1. 精简 iw 不输出 Supported Ciphers，能力读取返回未知。已在设备离线安装同版本 iw-full，并将构建依赖改为 iw-full。实际读到 CCMP／TKIP 等套件，没有 GCMP；不知道能力的其他设备仍保留原处理。
2. 新增的 `mu300.wifi-ciphers` 返回普通对象，不符合 LuCI require 模块必须导出构造器的契约，导致整个无线设置页无法加载。改用 `baseclass.extend()`，已热部署；回归补充构造器类型与实例化检查，避免只测 helper 绕过真实加载要求。

对应 ucode／前端回归 4 项及 Chromium 原生 Select 的三语言、保留已有无效值、独立 PHY 与读取失败流程通过。实机完成认证后打开 SIM 管理、无线设置和编辑弹窗，JS 异常为 0；CCMP 可选、GCMP 被过滤，没有保存无线配置。首次自动化打开已有主题登录页时另观察到 String.format 异常；认证后业务页无此异常，本轮未修改主题登录页。
