# VoLTE、VoNR 开关（2026-10-14）

网页“蜂窝 → 网络锁定”提供 VoLTE、VoNR 两项独立的单按钮滑动开关。行为与 E5 公共仓库对齐，使用 MU300 原有 Shell AT、异步任务与启动流程，没有引入 Python 依赖，也不需要重编内核。

- 控制“查看／控制卡槽”选择的 SIM，不切换上网卡，设置分别保存。
- 保留二次确认、切换卡槽后取消旧确认、互斥和错误提示。
- 配置跟随“开机自动应用”；正常平台路径在 AT 握手完成、射频开启和首次拨号之前回放。未配置时保持基带默认，不新增语音设置启动命令。
- 单独切换 VoLTE、VoNR，以及只有语音偏好的开机回放，均不执行 SFUN，不主动 ifup 或重拨。
- 网络模式、频段、小区的现有回放和晚期恢复流程保持原样；“清除全部蜂窝锁定”不删除或修改这两项语音偏好。
- 开关按真实回读显示，等待确认／任务完成后更新状态，状态未知或正在执行其他设置时禁用，不猜测为关闭。

指令与用户提供的 `UniSocCellularUtils.kt` 对齐：VoLTE 使用 `AT+CAVIMS`，VoNR 使用 `AT+SP5GCMDS="set nr param",45,<0|1>`，查询 `"get nr synch_param",42`。

VoLTE、VoNR 回读不一致时不保存。记录只对本次启动有效，不用旧开机的缓存或保存的偏好推断当前状态。单项查询失败时，不隐藏其他网络锁定功能，不用旧写入回执掩盖本次读取失败。

按用户最终要求移除独立 IMS 总开关：页面、RPC 和后端不再接受 `ims` 设置，不发送 `IMSEN` 查询或设置，启动检测和回放也忽略旧 `ims` 文件。旧文件仅原地保留，不转成 VoLTE 配置，不主动撤销此前已经下发给基带的设置。

关闭 VoLTE 或 VoNR 不能保证屏蔽传统网络的全部电话和短信；页面有对应说明。未改动用户的 IMS APN、NV、射频模式或当前 SIM 设置。

验证包括 dash／bash 下的锁定与异步任务测试、语音开关成功／失败、回读不一致、双卡文件隔离、仅语音配置的启动入口与单次回放、忽略旧 IMS 配置及拒绝旧接口、无额外 SFUN、重置保留偏好，以及实际页面开关双向切换、未知状态禁用、二次确认和三语言检查。

没有进行 MU300 实机部署或真实 VoLTE／VoNR 通话验证。此处记录最新源码行为，此前包含 IMS 开关的安装包不会随源码修改自动更新。
