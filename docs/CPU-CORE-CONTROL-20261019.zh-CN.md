# 网页逐核开关（2026-10-19）

用户要求：在网页 CPU 设置控制各核心开关，并可勾选开机自动应用。
这是用户主动选择的 CPU hotplug 功能，不是用强制关闭核心掩盖无线延迟，
也不把减少核心数量当作已测得的省电结论。

## 两仓库公共实现

- CPU 页面新增独立的“CPU 核心开关”卡片，显示每个实际 present 核心的
  在线状态；使用内核 `cpuN/online`，不写频率、电压、温控、AT、NV 或 eMMC。
- CPU0 保持在线。缺少 online 节点、不可写或状态无效的核心只读；不会
  通过改权限或替换驱动强行提供内核没有的 hotplug 能力。
- 只有点击“应用核心设置”才执行。未勾选“开机自动应用”时仅改变本次运行，
  同时移除这一项的开机配置；勾选后保存到 `/etc/unisoc-cpu-cores.json`。
  不修改已有调频、调压、温控的保存开关。
- “恢复核心初始状态”恢复本次运行首次设置前捕获的状态，并取消核心开关
  的开机保存。已有自动应用配置时，基线在启动回放前捕获；不宣称是所有
  原厂策略运行前的硬件出厂状态。
- `unisoc-cpu-cores` 为 START=99 的一次性服务，晚于现有调频恢复。
  没有保存配置时直接返回，不调用 ucode，不增加常驻进程、定时器或等待。
- 新装、离线机型 staging、插件安装和更新均包含组件、RPC ACL、启动链接
  及配置保留规则。E5/T551M/M8/T512N 共用 E5 插件路径；MU300/F50/V50/
  U30 Air 共用 MU300 插件路径，无机型名称判断。

## 写入与联动

后端先完整校验核心列表、布尔值、固定核心及重复项，再写 sysfs。先开启
需要的核心，再关闭其他核心；每次写入后读回，失败不重试、不继续执行后续
步骤。核心写入或保存失败时恢复已改动的核心，明确报告回滚是否完整。
配置通过临时文件与 rename 替换；这里只保证文件替换方式，不承诺突然断电
时配置一定落盘。开机回放错误保留原配置并在卡片显示，不自动重置整机或基带。

核心写入使用独立互斥锁，同时使用各仓库已有的调频写锁，避免和频率设置
并发操作。网页保留尚未应用的选择；可见页面沿用 LuCI 两秒刷新显示实际状态，
页面隐藏或离开后不发起本组件查询。应用后重新打开 CPU 页面可完整刷新由
hotplug 改变的调频策略列表，不擅自清空其他区域尚未提交的编辑。

MU300 的 policy 拓扑优先读取稳定的 `related_cpus`，而非随离线变化的
`affected_cpus`。两仓库都把全离线 CPU 簇的频率控件设为只读，并在保存其他
频率／温控设置时保留其已保存的频率请求。想修改离线簇的频率，需要先开启
对应核心。下一次正常开机先恢复频率，再应用用户保存的核心开关。

本功能不关闭内核平台自己的 hotplug 策略。如果平台同时改变核心状态，
会显示实际回读结果或报告拒绝，不循环强写和平台争抢。

## 验证范围

实际网页提交回归补充：HTTP ubus 会在参数中加入 `ubus_rpc_session`。
原输入校验误把它当成未知核心配置，导致命令行测试通过而网页应用报
`cpu_cores_invalid`。两仓库现仅在请求解析入口移除这个传输字段，再交给
原有严格配置校验；其他未知字段、CPU0 关闭及非法核心列表仍然拒绝，
会话字段不会进入保存文件。新增真实 ucode 回归覆盖带会话的临时／保存请求
及仍需拒绝的未知字段。U30 Air 已通过实际登录网页关闭／开启 CPU7、
勾选保存和恢复初始状态；测试配置清除，八核在线。此修复无需再次更换内核。

U30 Air 实机补齐时发现：已运行的 7.2.8 主线内核没有启用 `CONFIG_HOTPLUG_CPU`，
因而八个核心都没有 `online` 节点，仅部署网页会全部只读。MU300 公共主线配置
现显式启用该项，构建产物能力校验也将其列为必需项，防止打出仅有前端的包。
启用热插拔不会默认下线任何核心；原先用户指定的 CPU0 低延迟策略不变。

- 在实际 OpenWrt ucode 运行环境执行假 sysfs：发现 present 核心、CPU0 与
  固定核心保护、非法／重复／缺失／错误类型请求、临时设置、持久化、启动
  回放、恢复初始状态、只读文件系统注入的中途写入失败及保存失败回滚。
  全部写入限定容器临时目录，失败注入使用只读测试文件，不写主机 sysfs。
- E5 CPU 后端 23 项回归通过，包括离线簇配置保留。
- MU300 原有频率与温控实际 ucode 回归通过，新增稳定拓扑与离线配置保留场景。
- 新组件在两套 CPU 页面测试中／英／土、360/1280 宽度，验证固定核心不被
  误启用、草稿不被刷新覆盖、保存／取消保存／恢复／错误反馈及无横向溢出。
- 原 MU300 CPU 页面 24 组主题／语言／尺寸回归通过，频率／电压／温控
  独立保存及其他区域草稿保持正常。相关 JS 与 shell 语法检查、diff 检查通过。

2026-10-19 已在 U30 Air 完成部署和实机验证：

- 原内核 7.2.8 的 `CONFIG_HOTPLUG_CPU` 未启用，CPU0～7 均缺少 online 节点。
  已复用现有构建卷编译公共配置的新内核及完整配套模块；没有新增内核源码副本。
- 同步启动镜像实际加载的 26 个模块及根分区模块，启动分区写后回读一致，
  misc 未改。运行内核 `/sys/kernel/btf/vmlinux` 与构建 vmlinux 的 BTF 哈希相同，
  根分区完整模块清单校验通过；未出现 BTF／符号／vermagic 加载错误。
- 实际重启后，以八核全开的临时保存配置验证 S99 开机回放成功，日志返回 ok=1。
  随后逐个关闭、重新开启 CPU1～CPU7，均回读成功；CPU0 关闭请求被拒绝且状态不变。
  最终恢复八核在线，并删除测试用开机配置，不替用户选择核心或保存策略。
- 通过真实登录页面验证八个核心控件，其中七个可操作、CPU0 固定；页面刷新后
  没有 JavaScript 错误。网络／无线／基带配置校验和不变，WAN up=true、pending=false，
  热点恢复为 36 信道／80 MHz，CPU0 idle disable 保持 1/1/1，电压偏移仍为 0。
- 网页组件备份：`/root/hotfix-backups/20261019-cpu-cores`；内核及旧模块备份：
  `/root/hotfix-backups/20261019-cpu-hotplug`。

其他机型尚未实机验证，也没有重新打发布包。尚未测试关闭整个 CPU 簇、网络
负载或续航；单核开关通过不代表所有核心组合均已验证，不承诺一定降低功耗。
