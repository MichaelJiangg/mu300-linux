# 按卡控制蜂窝射频

入口：**蜂窝 → SIM 卡管理 → SIM 射频**。SIM1、SIM2 的开关独立保存，可同时关闭；不自动切换上网卡。关闭某张卡后，该卡无法通话、收发短信或上网。

## 实现

- `/etc/mu300/sim-radio` 原子保存两个允许位，缺失时默认 SIM1 允许、SIM2 关闭；已有明确设置保留，主动切到 SIM2 会保存启用。升级沿用原有 `/etc/mu300` 配置保留机制。
- 实际执行通过既有 mu300-at owner：按卡发送 `SFUN=5/4` 并用 `CFUN?` 核验（关闭为 0 或 2，开启为 1），保留 SIM 供电，不修改 NV。命令失败明确报错，并保留已保存的禁用意图。
- 复用上网卡切换门闩、mobile-data 的射频互斥和现有异步作业，避免与锁频、切卡、拨号交错。
- 普通双卡初始化保留握手、SIM 供电、工作模式和预拨号回放顺序；只让允许的协议栈启动。已在运行的另一卡不做 SFUN 重置。
- 数据卡禁用返回独立的 SIM_RADIO_DISABLED 状态，让 netifd 等待显式恢复；不循环唤醒。恢复使用 availability 通知，保留用户手动关闭数据时的 autostart=false。
- 切卡、设置触发的射频重连、首页射频开关、自动失网恢复均遵守同一设置。首页不再另走旧的 CFUN=0／SFUN 控制实现。
- 冷启动尚未上电的卡恢复时，调用既有初始化流程，不复制一套 SFUN／SPSWDATA 命令；没有新增常驻服务和 AT 轮询。

## U30 Air

保留原厂一次只工作的单张 RF 协议栈。允许另一槽不等于立即切到它；选择那张卡仍通过现有原生切卡流程。被禁用的卡不会由开机预热或热切卡自动重新打开。冷恢复复用原有预热器的 radio-only 入口，避免为等待 IP 自动回退到别的卡。

本次 U30 的冷／热切卡离线回归各 34 项通过，未做 U30 实机测试。

## F50 实机结果

以下是旧版 CFUN 实现的历史实测，不能作为新版 SFUN 的实机验证。2026-10-19 的源码修正见 [SFUN 修正](SIM-RADIO-SFUN-20261019.zh-CN.md)。

2026-10-17，在 7.2.8 上热部署：

1. 关闭 SIM2：回读 `[1,4]`，SIM1 的 WAN 保持连接。
2. 再关闭 SIM1：回读 `[4,4]`；等待期间没有自动复活。
3. 单独恢复 SIM2：回读 `[4,1]`，没有自动移动上网卡。
4. 恢复 SIM1：回读 `[1,1]`，WAN 自动取得地址。
5. 保存 SIM2 关闭并正常重启：新 boot ID 下仍为 `[1,4]`，SIM1 已联网。测试结束恢复原来的两卡允许状态。

共享网页覆盖确认、两卡分别控制、错误回显和卸载页面后的任务处理；命令测试覆盖保存失败／无效配置、互斥、禁用后持久化、冷恢复，以及双卡启动的全部允许位组合。其他机型未在本次进行实机测试。
